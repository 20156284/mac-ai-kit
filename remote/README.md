# Remotion 远程渲染配置与独立运行模块

交付文件是一个独立的 `start-remotion-remote.sh`，内嵌 Node.js 服务、Studio 适配器和内部监听保护。无需复制整个项目，不修改原项目的 scripts、配置或依赖，不自动安装任何软件。

## 前提

- macOS，当前终端已经启用 Node.js 24+、pnpm 和 Git。
- 现有 Remotion 项目已安装好依赖，且工作区干净。
- 当前分支配置了远端 upstream，Git 已具备非交互读取权限。配置时用 ls-remote 检查现有远端分支是否可读取，不执行 pull，不创建凭据。detached HEAD 或没有 upstream 时停止，不猜测分支、不改 Git 配置。
- 仅支持已核对源代码的 `@remotion/cli` 4.0.518 和 4.0.534，其他版本拒绝启动，不承诺兼容所有 Remotion 版本。
- 已挂载、可写的输出磁盘目录。脚本不会替你创建磁盘挂载点。

## 工具包入口：只配置，不运行

主工具包中的「配置远程渲染」只调用 `--configure`。以下独立命令也可完成同样的准备：

```sh
bash remote/start-remotion-remote.sh --project "/已有项目" --configure
```

未提供 `--project` 时先询问已有项目目录，回车使用当前目录，输入 q 取消。配置检查现有 Node.js、pnpm、Remotion 依赖和 Git 远端读取权限，询问已存在的输出目录、输出保留小时数（默认 0，不清理）、用户名和两次不回显的密码（至少 6 字符）。固定端口配置为公共入口 43871、内部 Studio 43872。明确输入 `YES` 后，只保存配置、带盐密码哈希和内嵌运行代码。

### 一共要输入什么

首次配置为 **5 项设置**，另有 **1 次重复密码 + 1 次 YES 确认**，合计 7 次输入。通过 `--project` 提供项目目录后不再问该项，交互为 6 次；独立脚本未指定动作时还需选择一次菜单，工具包自身的导航选择不计入配置项。

| 设置 | 必填 / 默认 | 规则 |
|---|---|---|
| 已有 Remotion Git 项目目录 | 可回车，默认当前工作目录；`--project` 可预填 | 本地已存在目录，不是 Git 仓库 URL；输入 q 取消 |
| 输出目录 | 必填，无默认值 | 已存在、已挂载、可写的目录；不自动创建 |
| 已完成输出保留小时 | 可回车，默认 0（不自动删除） | 0–87600 整数，正数启用到期清理 |
| 浏览器登录用户名 | 必填，无默认值 | 1 字符即可，允许中文；不允许冒号、控制字符或纯空白 |
| 浏览器登录密码 | 必填，无默认值 | 最低 6 字符、不回显、不自动 trim；建议使用更长密码 |

随后重复一次密码，并输入大写 `YES` 确认保存。密码首尾空格也是密码的一部分，两次必须完全相同。项目目录（包括 `--project`）、输出目录、保留小时和用户名会去掉首尾空白，保留中间空格。交互输入路径无需添加引号或反斜杠；命令行中的路径仍按 Shell 规则加引号。不执行 `eval`，不把粘贴内容当命令。

**没有要手填的远程 URL、端口、Git 地址或分支。** URL/端口固定，Git 远端和跟踪分支自动读取现有项目。`https://…`、`ssh://…`、`file://…` 不是这里的目录输入，脚本会给出明确提示；先自行 clone 或找到对应本地目录，再填写本地路径。

配置完成会显示具体配置文件、输出目录以及未来访问/下载地址；这不是服务已上线的提示。仅配置生成状态目录下的 `config.json`、`runtime.cjs`、`bind-guard.cjs`、`studio-adapter.cjs`，不生成视频、日志、版本缓存或 plist。后者在未来显式运行/安装时才可能生成。

`--configure` 不启动任何监听、Studio、推理或渲染，不执行 Git fetch/pull，不创建 LaunchAgent plist，不调用 launchctl bootstrap、kickstart 或 bootout，不停止/杀死已有进程。已有运行实例或已加载登录服务时直接停止配置，不覆盖现有配置。即使登录服务尚未加载，只要已有同名 plist 也会拒绝配置，以免影响下次登录启动；用户需要在工具包外自行处理旧服务。配置确认及实际写入前都会检查上述状态。

## 工具包外：显式运行控制（保留旧工作流）

下面是独立脚本的运行能力，不是工具包的环境准备步骤。只有用户另行明确运行这些命令才会启动或管理服务；工具包不透传这些运行参数：

```sh
bash remote/start-remotion-remote.sh --project "/项目" --foreground
bash remote/start-remotion-remote.sh --project "/项目" --install
bash remote/start-remotion-remote.sh --project "/项目" --status
bash remote/start-remotion-remote.sh --project "/项目" --stop
bash remote/start-remotion-remote.sh --project "/项目" --uninstall
```

直接打开独立脚本（不指定动作）显示菜单，包含「仅配置」和上述独立运行控制。`--foreground` 和 `--install` 保留原来的再次配置、确认流程，不会因为之前完成配置而自动启动。

`--install` 安装当前用户 LaunchAgent，只在该用户登录后启动，不是无需登录的系统开机服务。无需 sudo。重复安装会再次确认配置，并先停止属于本脚本的旧服务；不会覆盖归属不明的同名 plist。卸载仅移除登录服务，保留配置、缓存及所有渲染输出。

以下网络、更新、输出行为仅在工具包外显式启动服务之后发生，完成配置本身不会触发这些行为。

## 访问与安全边界

- 浏览器访问 `http://Mac的私网地址:43871/`，使用刚才设置的账号密码。
- 状态与成品下载页面：`/_remote/`；机器可读状态：`/_remote/status`，任务列表：`/_remote/jobs`。
- 公共入口监听所有网卡 `0.0.0.0:43871`，原生 Studio 内部端口为 `127.0.0.1:43872`。两个端口必须空闲。
- 原生 Studio 没有这里所需的官方 loopback 开关，因此内嵌保护代码限制子进程的实际监听并验证结果；不是仅设置无效的 HOST 环境变量。
- HTTP Basic 本身不加密。仅用于可信局域网或已配置的私有 VPN，不要把该 HTTP 端口直接映射到互联网。脚本不会配置 Tailscale、ZeroTier、TLS、网络、防火墙或路由器。
- 6 字符只是内网使用的最低门槛，并不代表强密码；仍建议更长且独有的密码。
- 密码通过标准输入计算带盐 scrypt 哈希，不作为命令行参数、不保存明文。服务配置及内嵌代码权限为 600，私有状态目录为 700。
- Studio 会执行项目代码。只有你信任的仓库、分支与提交才应接入；自动拉取并运行新提交意味着信任该远端的维护者。

## 更新与渲染

每 60 秒检查一次远端提交，不是每分钟重启 Studio。有变化时准备独立 Git worktree，仅在适配器明确确认渲染队列空闲后切换；无法确认、正在渲染或依赖配置变化时保留当前版本并在状态中说明。不会 reset、切换或清空主工作区，也不会自动安装依赖。Git fetch 和 worktree 元数据会写入原仓库的 Git 元数据，但主工作区文件不被更新。

依赖清单或锁文件改变时，请自行准备依赖并在维护窗口重新配置启动。新 worktree 使用现有 node_modules，不是每个版本各自全新安装。

输出被约束在所选目录的 `remotion-remote-jobs/<任务 UUID>/` 独立任务目录，成功渲染后可从输出页下载。默认保留小时数为 0，不自动清理。可主动设置正整数小时数；最终确认会明确提示本服务已完成输出到期后永久删除，即使尚未下载。仅清理服务登记的已完成输出，跳过正在下载的文件，不清理其他文件或历史代码版本。磁盘空间和历史代码版本仍需用户管理。单独音频输出不在此适配器支持范围内。磁盘未挂载、空间不足或状态不明确时应检查状态和日志，不要通过创建同名空文件夹绕过磁盘检查。

## 文件与排障

每个项目用绝对路径的哈希区分：

- `~/Library/Application Support/RemotionRemote/<项目标识>/`：配置、内嵌代码、独立版本缓存、日志。
- `~/Library/LaunchAgents/local.remotion.remote.<项目标识>.plist`：用户登录服务。

状态命令显示本项目的具体路径与 launchctl 状态。日志为状态目录中的 `service.log` 和 `service-error.log`。前台运行显示运行时错误。登录服务能访问的 SSH agent / 凭据环境可能与当前终端不同；如果配置检查成功但登录后拉取失败，服务会报告失败，请自行检查该登录会话的 Git 认证。不会跳过认证或创建新凭据。更换输出目录或密码可重新执行配置流程；仅配置模式要求没有运行实例和登录启动 plist。停止命令针对登录服务；前台进程请在其终端按 Ctrl-C。

这是已经做过静态和隔离测试的交付脚本，不代表已经在你的 Mac 上安装或完成真实项目端到端验证。工具包到保存配置为止。如日后另行决定启用运行服务，建议先在工具包外前台验证私网登录、实际渲染、输出下载及繁忙时更新等待，再决定是否安装登录自启动。

## 本地维护测试

`src/launcher.sh` 是打包模板，不能直接作为正式发行文件运行。打包时用相邻 runtime、bind-guard、studio-adapter 的 Base64 内容替换末尾三个 payload 占位符。

```sh
bash -n src/launcher.sh
python -m unittest discover -s tests -p test_launcher.py -v
```

启动器测试使用假 macOS、Git、launchctl、pnpm 和假运行时，不调用真实 launchctl、不访问网络、不安装软件。运行时测试另见 tests 中相应文件。

失败或未知任务会阻止自动切换，需在维护窗口排查并重启；运行中不要改动所复用的 node_modules。历史 worktree 缓存不会自动清理。
