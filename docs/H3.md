# H3：版本选择、共用文件与音频参考

## 先选对模型

H3 FL2VA 和 REF2VA 是两个不同的 checkpoint，不是给同一个模型切换参数：

- **FL2VA**：首帧/末帧约束，不接受参考音频、参考视频或参考图像数组。
- **REF2VA**：参考图片、视频、音频条件；不能同时把它当作首帧/末帧模型，也不支持 chain_windows > 1。
- 两套均为 MLX-Serve 专用 8bit 混合精度包，不是全 BF16。查看模型目录的 config.json 中 tasks 区分，不只看“MiniMax H3”简称。

要用现有音乐作为参考，选择 **REF2VA**。核查的 MLX-Serve v26.10.2 对 FL2VA 收到 ref_audios 的请求明确返回 HTTP 400；不是把音频文件改名或替换请求字段就能解决。

下载和启动都在工具包根目录的终端运行 `bash start.sh` 进入。模型放在共享根：

- `video/MiniMax-H3-FL2VA-MLX-Serve-8bit/`
- `video/MiniMax-H3-REF2VA-MLX-Serve-8bit/`

目录保留原仓库名及大小写。旧目录不自动迁移、删除或重命名。下载完成后由用户另行通过 App、CLI 或 llama-swap 使用；本包不启动推理。选择「合并 H3 共享权重」会自动检查当前模型目录中的两版，对完整 SHA256 一致的共享文件去重；缺少另一版时不会擅自下载。

## 下载两套时避免重复

按核实快照，FL2VA 为 70,076,153,374 字节（含 Turbo LoRA），REF2VA 为 69,296,302,685 字节（无 Turbo LoRA）。两套共有 10 个 SHA256 与大小均相同的文件，共 34,047,317,046 字节。完整两套约 139.37GB；去重后唯一文件约 105.33GB，省约 34.05GB。已有完整 FL2VA 时补 REF2VA 需要约 35.25GB 不同文件，反向需约 36.03GB；均为十进制文件统计，不含缓存与临时空间。

两套有相同的编码器、VAE 等配套文件，但 transformer 与配置等差异必须保留。不能把一个模型的主权重链接给另一个，也不能仅按文件名或大小判断相同。

「管理本地模型 → 下载模型」可分别或同时选择两版。普通下载 FL2VA 或 REF2VA 都会自动检查本次模型根目录中清单对应的两个版本目录，以及旧版已分发默认目录 `video/h3-mlx-8bit`；不需要先进入手动复用入口。两版同选时优先处理已有版本，共有文件只下载一次。其他位置的已有权重仍可用「管理本地模型 → 复用已有 H3 权重」，从候选编号选择或输入完整目录；维护者参数为 `--reuse-from /已有目录`。

复用以清单中的 SHA256 为依据：先校验来源文件，只有内容匹配才组装链接；缺失或不同的文件仍从目标模型的官方仓库下载。保留各自完整模型目录，服务仍按该目录加载。文件复用不代表两个模型可以同时驻留，也不代表省掉推理内存。

除上述限定目录外，不会自动扫描其他目录或用户磁盘；旧版本已下载在其他位置时，显式提供其现有目录作为复用来源。自动检测不跟随越出当前模型根目录的来源链接，断链、循环链接及 SHA256 不符的来源文件不会被复用；已有目标文件损坏则停止，不覆盖。不同 transformer 内容不能共享。来源目录不会被改写、搬走或删除。链接依赖原文件一直可读：不要移动、拔掉其磁盘或删除来源，否则目标模型也会失效；两套均应在挂载完成后使用。

复用大权重需要完整读取校验，可能明显耗时。空间显示是估算，不含所有缓存、临时文件和运行峰值。发生校验不匹配时以工具报告为准，不绕过校验或手工把未核实文件强行链接过去。

## 音频参考 API

已核查接口为 `POST /v1/video/generations`，H3 的字段是 **ref_audios：base64 WAV 字符串数组**，不是 LTX 的 audio 字段，也不是本地文件路径或 URL。

- ref_audios：最多 3 段 WAV；上游接受不同采样率和声道数，核查代码支持 PCM16、PCM24、float32 WAV。
- ref_images：最多 9 张 base64 PNG/JPEG。
- ref_videos：最多 3 项，每项含 frames 数组和可选的 base64 WAV audio。
- 三类合计最多 12 个参考文件。编号按各类型从 1 开始；纯音频参考可在提示词中引用 `<Audio 1>`。
- 每个参考都会增加生成成本。参考视频还会按引擎帧数阶梯裁剪，与生成长度有关。

准备你有权使用的本地 WAV。以下是**未执行的本机请求示例**，不负责下载或制作参考音频；请先核对许可、启动 REF2VA，并将 model_id 改成该本机服务实际公布的模型 ID。运行代码会提交一次视频生成任务，安装菜单不会自动执行它。

```python
import base64
import json
from pathlib import Path
from urllib.request import Request, urlopen

wav_path = Path.home() / "Music" / "reference.wav"  # 你准备的本地 WAV
model_id = "替换为本机服务实际公布的 REF2VA 模型 ID"
payload = {
    "model": model_id,
    "stream": True,
    "prompt": "参考 <Audio 1> 的音乐氛围，生成相应的视听场景。",
    "ref_audios": [base64.b64encode(wav_path.read_bytes()).decode("ascii")],
}
request = Request(
    "http://127.0.0.1:11234/v1/video/generations",
    data=json.dumps(payload).encode("utf-8"),
    headers={"Content-Type": "application/json"},
    method="POST",
)
with urlopen(request, timeout=3600) as response:
    for line in response:  # SSE 流；仅观察文本，不自动处理媒体负载
        text = line.decode("utf-8", errors="replace").rstrip()
        if text:
            print(text[:240])  # 避免把大段 base64 媒体打印满终端
```

这是 MLX-Serve 的视频生成接口，不是 sd.cpp 的异步任务接口。SSE 最终 data 事件的 type 为 complete，含 frames、height、width、fps、format: rgb8、base64 data；音频字段为 audio_sample_rate、audio_channels、audio_format: pcm_s16le 与 base64 audio_data。非流式返回相应 JSON。它们包含原始 RGB 视频帧与 PCM 音频数据，不能直接保存为 .mp4，也不应套用 sd.cpp 的任务 ID 轮询方式。上面的示例仅说明本机提交与读取流，不负责解码、排列帧、音频转换或封装成片；要观看成片，请使用匹配版本的官方客户端处理结果，或另行实现与该协议一致的媒体封装。

长生成可能等待较久；示例网络读取超时为 3600 秒，不代表性能保证或总时限。遇到断开/超时，先检查本机服务状态，勿盲目重试造成重复重任务。这里只给音频参考字段示例，不承诺默认分辨率、长度或采样设置适合你的机器。

## 不应承诺的效果

参考音频是生成条件，不是把原 WAV 原样贴入成片的保证。不能据此保证精确口型、逐字歌词对齐、旋律完全复刻，或原音轨逐样保留。若成片必须保留原音轨，需要另做后期合成与同步检查；本包不会自动替换或拼接音轨。

H3 地域、用途和商用条件仍适用，下载可用不等于许可适用。没有在用户 Mac 上加载、生成或测性能；静态源码和权重元数据核查不能替代实机验收。

核查快照：FL2VA 提交 caa4d86c9770a97ff35a610aa5dfcd63d0e2815a；REF2VA 提交 10283766961b5c4015d0ea1f9e12b915b634360d。其他修订可能改变差异，仍以下载时的清单与校验结果为准。

## 中断与磁盘

H3 下载使用目标旁的受控暂存目录；下载中断时保留，重新运行相同计划会核验已有完整文件并让客户端下载剩余部分。仅组装完成且全量核验成功后清理本工具创建的暂存目录。来源文件不移动、不删除。

推荐使用 APFS 磁盘：目标文件系统需要支持符号链接以及同盘硬链接；不支持时报告失败，不悄悄复制另一份大权重。跨卷的符号链接仍要求来源卷一直挂载且路径稳定。暂存与目标同盘，最终安装使用硬链接，不额外复制一套大文件。首次验证及重跑会完整读取相关大权重，可能需要数分钟。
