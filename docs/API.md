# 已安装项目的 API.md

统一入口 `bash start.sh` 的「环境诊断与 API 说明 → 生成或更新 API.md」 可指定安装根或模型根目录；也可运行：

```bash
bash start.sh api --directory "/你的安装目录或模型根目录"
```

这会在指定目录维护 `API.md`。它只检查本包清单认识的程序/模型文件，不全盘扫描、不执行发现的程序、不下载、不启动服务、不发生成请求。安装根可识别 `bin/` 包装器及 `models/`；模型根按清单子目录检查。默认范围内才考虑官方 App/Hermes 常见位置，不据此扫描任意其他盘。

- 只记录实际发现的已知项目，缺文件或尺寸不符会说明，不因目录名相似就声称完整安装。
- 文件和尺寸匹配不是 SHA256 全量校验，也不证明程序版本、Metal 支持或推理成功；目录内已有其他版本时，模板中的固定版本仅为接口核查基准。
- 程序、模型、配置、进程启动、HTTP 就绪分别判断；端口是示例，不代表正在监听。只有模型没有运行时的情况下，文档仍展示模型格式及接口参考，并提示运行时缺失。
- 显式检查/更新文档时，只更新本包的标记区，保留用户原有内容。无标记的已有文件追加管理区；重复运行不重复追加。标记损坏或写入失败时停止，不覆盖用户说明。先完整生成并写入同目录临时文件，成功后原子替换 `API.md`；不再生成 `API.md.bak.*`，不清理已有备份。模型合并的恢复备份和应用偏好备份不受影响。
- 不删除已有模型或旧 API 内容中的用户笔记；从新下载菜单移除 Whisper 不会卸载用户原来的 Whisper。
- 支持的 start.sh 安装/下载流程结束后会尝试更新相应目录。直接运行底层维护脚本时，不承诺自动更新，请再运行「环境诊断与 API 说明 → 生成或更新 API.md」。

每个已识别主模型的说明包括：实际路径、匹配运行时、版本来源、启动/配置前提及调用示例。Qwen3-ASR 使用 audio.cpp multipart 转写；YuE2 使用 audio.cpp offline tasks；Music3 与 H3 使用 MLX-Serve 的不同媒体路由；图像使用 sd.cpp。不能把“OpenAI 兼容”理解成所有服务接受同一个 JSON 或支持全部端点。

所有示例都要你明确执行才生效。Python 示例使用标准库；输出采取拒绝覆盖写入。音视频可能耗时较长、占用大量内存，超时不要盲目重试。此包没有在用户 Mac 安装、加载或进行性能验收。

模板源为 `config/api_templates.json`，按固定版本主要源码/文档核查。Krea2 Turbo 的固定版文档未提供专属采样配方，模板明确保留该缺口，不照抄 Raw 设置。Qwen3.8-27B BF16 包含独立 MTP 组件和本地键名前缀适配；API 模板给出关闭运行时量化的环境变量与参数。检查会把兼容产物也纳入完整性，仍不代表实际加载或推理已经通过。

## 已运行 LLM 接口测速

「Benchmark → Llama benchmark」只读查询用户指定 base URL 的 `/models`（通常为 `/v1/models`），单模型自动、多模型编号选择；返回 id 保持为推理请求中的 model，不拿原仓库名替换服务 alias。模型列表不证明已加载。随后从当前模型根目录自动匹配同源 tokenizer，选好参数后开始测试，不额外询问 yes。发现失败返回菜单，不改服务配置。细节及准确性限制见 [Benchmark 说明](BENCHMARK.md)。

## SD.cpp 原生模型切换

配置独立服务后，模型目录的 API.md 自动生成实际地址、模型加载与卸载示例。首次启动默认加载 Qwen；在同一 WebUI 选择 Qwen Image 2.1 Turbo / Krea 2 Turbo 并加载，或调用 `/sdcpp/v1/models/load`。详细请求与错误行为见 [原生服务](NATIVE_SERVICES.md#在同一个-sdcpp-服务切换模型)。

服务启动采用只补缺失内容的方式，不覆盖已有说明；停止服务、查看状态与日志均不修改本文档。历史探测结果不代表当前服务在线。


## Agent 主动协调媒体服务

本地生成的模型目录 `API.md` 会在启动或显式 API 更新时追加“Agent 资源协调与主动启停”，不是覆盖手写内容。该段记录本次实际工具包、服务根和模型根的绝对路径，路径含空格或引号时已做 shell 引用；同一上下文重复运行不重复追加，移动工具包后追加新路径版本，以最后一段为准。

策略是用户指定的：保留且预先验证大语言模型已加载 / 可响应；视频与 SD.cpp 制图及 audio.cpp 音频互斥。工具包不托管视频或 MLX App，不能整体退出 App 来释放视频内存，也不保证各安装版本的视频调度能与 LLM 交错执行。

Agent 可用生成的无菜单命令查看 `status --json`、单独启动，或在掌握所有提交方且确认所有任务已排空 / 无新请求，或用户明确确认当前可停止后，单独停止原生服务。`unknown`、超时、客户端离线、健康检查、模型 ready/empty 均不是安全停机证明；没有实现原子的关闭入口与排空屏障，不应拼出无人值守的“查 idle 后立刻 stop”脚本。JSON unknown 本身不授权停止，但若 Agent 另有可靠的独占协调及全部任务终态证据，可按策略主动执行，无需逐次询问；无法建立这些保证时等待或询问。视频结束后仅按下一个任务启动需要的一项，不自动全部恢复。

详见 [服务管理的 Agent 资源协调与 JSON 快照](NATIVE_SERVICES.md#agent-资源协调与-json-快照)。
